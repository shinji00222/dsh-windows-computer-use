## 真实窗口覆盖

### preview.2 修复验证

- 修复后完成五轮独立进程冷启动回归，每轮 19/19 通过；断言包含真实目标上的中文、点击、双击、拖动、滚轮、OCR、取消与延迟 Esc，以及 UI 线程忙碌时的激活。
- 可控复现：专用窗口的 UI 线程暂停 900 毫秒。旧激活代码失败，报告 `FOREGROUND_DENIED`（17/19）；新代码等待实际前台状态后同一回归通过（19/19）。去掉 `AttachThreadInput`，避免将自身输入队列绑定到可能阻塞的外部 UI 线程。
- 激活等待分为两次最多 1200 毫秒，第二次仅执行一次 Alt 释放前台锁的尝试；每 20 毫秒检查取消，失败仍明确拒绝，绝不重放用户输入。
- Esc 专用按钮延迟 450 毫秒发送真实键盘事件，测试等待原生钩子计数增加，再严格验证同轮拒绝和新轮恢复；不再把固定 200 毫秒睡眠当作事件已送达的证据。停止线程的消息循环实际就绪后才报告 ready。
- 上轮首次失败没有保留完整桌面现场，不能声称已证明其全部原因；本版修复的是已复现的激活时序缺陷，并增加了 Esc 的可观测证据。
- 首轮耐久测试第三轮发现双击事件未被目标确认，测试如实失败。双击改为一次 `SendInput` 提交四个事件，消除分次提交中的调度间隔，并在点击前重验焦点与指针；未改变“必须观察到目标双击事件”的断言。历史失败具体由调度还是外部输入引起，缺乏现场证据，不作断言。[SendInput 批量事件保证](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)。

依据：[Windows 跨线程激活是异步的](https://devblogs.microsoft.com/oldnewthing/20161118-00/?p=94745)、[UIA Invoke 返回不保证效果已完成](https://learn.microsoft.com/en-us/dotnet/api/system.windows.automation.invokepattern.invoke?view=windowsdesktop-10.0)。

## 协议与边界

官方 MCP SDK 初始化、工具发现、真实 C# health、参数类型与未知字段拒绝、只读模式拒绝输入均已测试。宿主桥接独立验证，不把普通 Node 进程成功当成 DSH 成功。

未证明：所有桌面应用兼容性、所有 OCR 语言和字体、后台输入、WGC、UAC 安全桌面、完整真实模型任务成功率、用户当前 DSH 窗口中的设置交互。GitHub CI 的远端结果需单独核对，不把本机通过写成远端通过。

## 已处理的环境问题

- 单文件 .NET 引擎因本机临时解压目录权限失败；改用自包含目录发行，消除该启动依赖。
- 隐藏控制台启动会影响 WinForms 首次窗口显示；测试窗口显式显示并核对可见性。
- SetForegroundWindow 可受 Windows 前台锁限制；采用受限输入线程附加并确保释放，再核对实际前台。
- OCR 测试窗口的标签曾被裁切；修正窗口布局后从真实截图和 OCR 结果验证，而不是放宽到任意非空文本。
- PowerShell 直接调用 GUI EXE 的返回值不足以证明子进程通过；宿主测试改为 Node `spawnSync` 等待并核对真实退出状态与断言输出。

- preview.3 首次 CI 在批次开始前报控件检查失败，后续依赖步骤随之失败。布局遍历预算从 150ms 调整为 1000ms，保留不完整即停止规则，并区分错误原因；本机 24/24 再次通过，远端需以修复后的运行结果为准。
